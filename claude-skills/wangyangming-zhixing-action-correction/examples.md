# 使用示例

## 示例一：课程学很多，项目没开始

【调用】知行差距诊断助手 + 自我欺骗检查助手

【作用】检查你是真的缺关键能力，还是已经知道第一步，却用“还没准备好”避开真实反馈。

【经典依据】来源：《传习录》卷中《答顾东桥书》第 136 条。核心思想：学习本身包含实践。原文：“尽天下之学，无有不行而可以言学者。”现代化解释：先用小项目暴露具体缺口，再定向补课，比继续泛学更能判断你缺什么。

【判断】目前更像“准备范围没有边界”，但这只是初步判断；如果项目确实要求你尚未掌握的安全或关键技术，应更新判断。

【解决方案】A：继续系统学习，但先写明阻止开工的具体知识。B：做一个低风险最小项目，用结果暴露缺口。

【推荐方案】当前先选 B。若做到第一功能时出现一个明确、无法绕过的基础缺口，再更新判断并切到针对性补课。

【下一步】写下一个 60 分钟内可完成、能交给真实用户看的最小功能，并在今天开始制作。

## 示例二：知道该结束合作却拖延

不能直接判定“知行不合一”。先检查合同义务、退出损失、对方权益、安全风险和用户真正认可的底线。推荐只能是当前一个动作，例如先整理退出条件并约一次正式沟通；若关键法律后果不清，先咨询专业人士。

## 示例三：项目失败后全怪自己

先以责任边界助手为主：分开市场变化、他人违约、随机事件、可影响因素和用户可控动作；再用反省纠偏助手检查假设、决策和执行。最终修改一个具体动作，不输出“你能力不够”这类人格结论。
